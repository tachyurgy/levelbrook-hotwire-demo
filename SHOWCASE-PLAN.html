The Hotwire Showcase
— a portfolio, not a demo.

demo.levelbrook.com stops being one Jira clone. It becomes a switcher that opens into a roster of distinct, production-grade Rails 8 apps — each one proving a different corner of the modern Hotwire stack, each mined from the 35 reference repos under c2c/docs/hotwire-research/repos/.

Why this shape

A single workspace app answers one question well — "can you build a Linear-lite?" A recruiter or Rails lead asks a bigger one: "can this team reach for the right Hotwire primitive across very different product surfaces?" The portfolio answers that by showing the same author shipping realtime collaboration, optimistic UI, server-rendered dashboards, spreadsheet-grade inline editing, and permanent-state media — all without a SPA. One themeable shell, one DB, six products.

Architecture in one breath

  • Root / is the switcher — a gallery of app cards (name, domain, accent, the Hotwire primitives each one demonstrates). This replaces the old workspace dashboard as the front door.
  • One themeable shell. A Showcase::APPS registry defines each app's name, tagline, accent color pair, and nav. The layout re-themes instantly by overriding --color-accent on a wrapper and rendering that app's sidebar/topbar. Existing workspace views are untouched because they already read var(--color-accent).
  • Each app is a real namespace — its own models, controllers, views, Stimulus controllers, broadcasts, and seed data. Distinct domains so no two cards feel like the same app re-skinned.
  • Shared connective tissue — toast side-channel, the inline search, View Transitions meta, morph-by-default — lives once in the base layout.

The three things that were wrong — and the fixes

1 · The ambient audio was bolted onto a Jira board

It auto-presented a "Deep Focus — Ambient Loop" on the delivery board, which read as noise on a work tool. Fix: delete the persistent player from the workspace entirely (_player.html.erb, player_controller.js, the layout include, the asset). The technique it was demonstrating (data-turbo-permanent surviving navigation) is real and worth showing — so it moves to Spindle, a music app where audio is the point and is only ever started by the user. Right technique, right home.

2 · Search opened a "weird modal" and wasn't snappy

Two offenders: the /search page's results linked into a <dialog> modal, and the topbar "Search anything" launched the ⌘K <dialog> palette. Fix: an inline combobox in the topbar — click the box and a results panel drops down right underneath it (absolutely positioned, not a dialog), debounced to ~120 ms, server-rendered into a Turbo Frame, keyboard-navigable (↑/↓/↵), dismiss on blur/Esc. ⌘K simply focuses that same box. Pattern lifted from hotwire_combobox (its filtering/navigation/selection split) and stimulus-autocomplete. No modal anywhere in the search path.

3 · Lag when clicking the inline-edit inputs

Entering edit mode did a server round-trip: click title → GET /issues/:id/field/title → frame swaps to the form. That network hop is the lag. Fix: render display and edit markup in the field frame up front; a tiny Stimulus inline-edit controller toggles to the input instantly on click and focuses it (zero round-trip). Submitting still hits the server, which returns the updated display partial and re-broadcasts — so the server stays authoritative and other clients still morph. Snappy on click, correct on save.

Build order

  1. Foundation — Showcase::APPS registry, gallery switcher at root, themeable shell, base layout (toasts + View Transitions + inline search) — no more per-app sidebar duplication.
  2. Workspace fixes — kill audio, inline search, instant inline edit. (The three explicit asks.)
  3. Ballot — highest visual wow per line of code; pure broadcast-morph + optimistic.
  4. Pulse — morphing charts + a streamed deploy job; proves the job→stream loop.
  5. Spindle — re-homes the persistent player honestly.
  6. Grid — spreadsheet inline edit + formula recalc.
  7. Cadence — promote chat to its own themed app, add optimistic reactions.
  8. Verify + deploy — extend tests, boot-check, kamal deploy to demo.levelbrook.com, confirm every app route 200s over HTTPS.

Non-negotiables carried from the research strategy

  • Every app is progressively enhanced: works without JS, faster with it.
  • broadcasts_refreshes + morph is the default realtime strategy; explicit broadcast_append_to only for append feeds (chat, activity).
  • Each feature shows the working UI first, then a one-line "Technique" caption — never an explainer card in place of a working feature.
  • No fabricated metrics, logos, or testimonials. Brand-only, anonymous (per Levelbrook identity rules).
